Purpose
-------

BASE-06G.2 added opt-in structural tracing to the validated FlexRIC
xapp_oran_moni KPM callback and used it to inspect the relationship between
measurement descriptors and measurement records before the original callback
performed indexed access.

The trace is enabled only when:

    TCD_KPM_STRUCT_TRACE=1

Trace output is JSON Lines written to stderr. The original collector output,
KPM subscription configuration and validated callback bounds correction remain
unchanged.

Semantic result
---------------

The runtime trace confirmed that the KPM message may contain measurement data
and measurement descriptor lists of different lengths.

A representative observed container contained:

    meas_data_lst_len = 3
    meas_info_lst_len = 2

The trace classified:

    mapping_status=length_mismatch records: 351
    records where mapping_status was not applicable: 139

The records without mapping_status correspond to structural events such as
indication, UE-report and index events; they are not malformed records.

This result is consistent with the previously closed SIGSEGV root cause:
iteration over the longer measurement-record sequence could index the shorter
measurement-information sequence without a corresponding bounds condition.
