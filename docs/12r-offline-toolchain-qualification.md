# Prompt 12R offline toolchain qualification and redesign boundary

## 1. Purpose

Prompt 12R was opened because Prompt 12 system identification had begun to
mix two different classes of behaviour:

1. O-RAN plant dynamics caused by a controlled PRB transition; and
2. failures or instability of the experimental platform and experiment
   tooling.

The redesign rule is therefore:

`MODEL_VALID = PLATFORM_HEALTHY`

A scientific model must not absorb failures of the gNB, UE, 5GC, RIC/E2,
Docker/network lifecycle, disk, timestamps, telemetry acquisition, or
experiment tooling.

No new scientific PRB control is authorised by this record.

## 2. Runtime boundary

The live testbed was intentionally left in a clean stopped state before the
offline redesign work.

Prompt 12R offline qualification does not require day-start.

All qualification described here is repository inspection, historical
evidence replay, or temporary `/tmp` regression work.

## 4. R01V3 identity root cause

The repository-wide Prompt 12 run identity contract is:

`RUN-YYYYMMDDTHHMMSSZ-NNN`

The canonical regex is:

`^RUN-[0-9]{8}T[0-9]{6}Z-[0-9]{3}$`

The shared identity generator uses a three-digit sequence through `%03d`.

R01V3 instead received the literal identity:

`RUN-20260827T180525Z-54020`

The five-digit suffix was present before canonicalization and was propagated
through the R01V3 namespace, prearm, workload, and closeout evidence.

Shell-history reconstruction showed that the value was hard-coded into the
ad-hoc R01V3 procedure rather than generated by the shared identity library.

The invalid identity nevertheless passed:

- `NAMESPACE_FREEZE_GATE=PASS`;
- `PREARM_GATE=PASS`;
- `WORKLOAD_START_GATE=PASS`.

The shared identity library rejects the same run ID.

Therefore the root cause is an early identity-admission gap caused by an
ad-hoc experimental path that bypassed canonical identity validation.

Identity validation must be a fail-fast precondition before scientific
namespace creation, actuator prearm, or workload launch.

## 7. Executor deterministic-replay gap

Before repair, the atomic precontrol executor always used:

`time.time_ns()`

for `executor_start_ns`.

Therefore a historical precontrol fixture with a valid historical decision
time could not be replayed deterministically: the executor compared the old
sample against the current wall clock and correctly failed closed as stale.

The demonstrated historical-replay failure was:

- mode: `no-control`;
- executor gate: `FAIL_CLOSED`;
- reason: `EXECUTOR_START_SAMPLE_AGE_OUT_OF_BOUNDS`;
- control executed: NO;
- trigger write attempts: 0.

This was an offline replayability defect, not a defect in live freshness
protection.

## 8. Prospective executor repair

The executor now accepts an optional:

`--executor-start-utc-ns`

argument.

The override is deliberately restricted to:

`mode=no-control`

The live `fifo` path rejects the same argument fail-closed with:

`EXECUTOR_START_OVERRIDE_FORBIDDEN_IN_FIFO_MODE`

Therefore live scientific timing continues to use the system clock.

The repair also adds an explicit causality gate:

`executor_start_utc_ns >= source decision_utc_ns`

An injected executor timestamp before the source decision fails closed with:

`EXECUTOR_START_PRECEDES_SOURCE_DECISION`

`10f9a1bf98efac435e76a3d3891cd41bea987e58b8bf3536ef9c92ad4d6cbd19`

## 11. Architectural consequences for Prompt 12R

Prospective experiment execution must not rely on ad-hoc shell blocks for
scientific identity or admission.

The redesign must provide a single transaction boundary with fail-fast
identity validation and explicit states equivalent to:

`NEW`
`-> DEPLOYED`
`-> PLATFORM_QUALIFIED`
`-> INITIAL_STATE_VERIFIED`
`-> ACTUATOR_ARMED`
`-> WORKLOAD_READY`
`-> PRESTEP_ADMITTED`
`-> TRIGGERED_EXACTLY_ONCE`
`-> APPLIED_VERIFIED`
`-> POSTSTEP_COMPLETE`
`-> SCIENTIFICALLY_ADJUDICATED`
`-> CLOSED`
`-> DESTROYED`

Required failure states include:

- `ABORTED_PRETRIGGER`;
- `INVALID_POSTTRIGGER`;
- `PLATFORM_FAILURE`;
- `TOOLING_FAILURE`.

## 12. Next redesign stage

Offline precontrol-toolchain qualification is sufficiently complete to stop
investigating the R01V3 five-digit identity defect.

The next Prompt 12R stage is platform-health architecture.

That stage must define the platform qualification contract independently of
plant dynamics, including at least:

- required base containers;
- zero unexpected restart counts;
- 5GC health;
- UE attachment;
- gNB health;
- RIC/E2 connectivity;
- initial PRB state;
- fresh telemetry;
- receiver continuity;
- absence of stale iperf processes;
- disk-space headroom;
- timestamp sanity;
- expected network path.

Only after the platform-health contract, transaction state machine,
bounded-duration policy, and prospective protocol amendment are qualified may
a new live scientific repetition be considered.
